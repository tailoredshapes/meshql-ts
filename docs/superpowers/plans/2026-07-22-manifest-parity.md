# Manifest Parity (TypeScript) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port meshql-rs's deployment manifest (schema, generator, conformance tests, HTTP serving) to `meshobj` (TypeScript), wired into `examples/farm`.

**Architecture:** A `generate(configDir)` function in `examples/farm/manifest.ts` reads `config/graph/*.graphql` + `config/json/*.schema.json` directly off disk and emits a `manifest.schema.json`-conformant object. The committed `examples/farm/config/manifest.json` is regenerated by a small script and served at `GET /manifest` by a new `examples/farm/index.ts` entrypoint (replacing this example's current reliance on the generic `@tailoredshapes/meshql-cli` binary, whose package export is currently broken anyway — see Task 5).

**Tech Stack:** TypeScript, Node 20, Express (`@tailoredshapes/meshql-server`'s `init`), `ajv`/`ajv-formats` (already a dependency), Vitest.

**Spec:** `/tank/repos/tailoredshapes/meshql-rs/docs/superpowers/specs/2026-07-22-manifest-parity-design.md` (this repo is `/tank/repos/tailoredshapes/meshobj`, a sibling repo — the spec lives in `meshql-rs` because that's where the manifest concept originated).

**Before starting:** confirm Node 20 is active (`node --version` — this repo's `package.json` pins `engines.node: ">=20 <21"`; if the environment defaults to a newer Node, `nvm use 20` first, matching how this was handled in the same environment during the earlier "honesty headers" port).

```typescript
import * as fs from 'fs';
import * as path from 'path';

/**
 * Builds the deployment manifest (schemas/manifest.schema.json) from
 * config/graph/*.graphql and config/json/*.schema.json. Mirrors
 * meshql-rs's examples/egg-economy/src/manifest.rs: reads the config
 * directory directly (not the parsed HOCON Config object), deterministic
 * (sorted by filename), path convention by construction
 * (/{entity}/graph, /{entity}/api).
 */
export function generate(configDir: string): Record<string, any> {
    const graphDir = path.join(configDir, 'graph');
    const jsonDir = path.join(configDir, 'json');

    const graphqlFiles = fs
        .readdirSync(graphDir)
        .filter((f) => f.endsWith('.graphql'))
        .sort();

    const entities: Record<string, any> = {};

    for (const filename of graphqlFiles) {
        const entity = filename.slice(0, -'.graphql'.length);
        const graphqlText = fs.readFileSync(path.join(graphDir, filename), 'utf8');

        const surfaces: Record<string, any> = {
            graph: { kind: 'graphql', path: `/${entity}/graph`, schema: graphqlText },
        };

        const jsonSchemaPath = path.join(jsonDir, `${entity}.schema.json`);
        if (fs.existsSync(jsonSchemaPath)) {
            const jsonSchema = JSON.parse(fs.readFileSync(jsonSchemaPath, 'utf8'));
            surfaces.api = { kind: 'rest', path: `/${entity}/api`, schema: jsonSchema };
        }

        entities[entity] = { surfaces };
    }

    return { meshql: 1, entities, surfaces: {} };
}
```

## Task 4: Conformance tests

**Files:**
- Create: `examples/farm/test/manifest.spec.ts`

`manifest.schema.json` declares `"$schema": "https://json-schema.org/draft/2020-12/schema"` — plain `Ajv` (the default export) only supports draft-07. Use `ajv/dist/2020` (`Ajv2020`), confirmed available in the workspace's installed `ajv@8.17.1`.

- [ ] **Step 1: Write the test class**

```typescript
import { describe, it, expect } from 'vitest';
import Ajv2020 from 'ajv/dist/2020';
import * as fs from 'fs';
import * as path from 'path';
import { generate } from '../manifest';

const configDir = path.resolve(__dirname, '../config');
const schemaPath = path.resolve(__dirname, '../../../schemas/manifest.schema.json');
const manifestPath = path.join(configDir, 'manifest.json');

describe('manifest conformance', () => {
    it('validates against the published schema', () => {
        const schema = JSON.parse(fs.readFileSync(schemaPath, 'utf8'));
        const manifest = JSON.parse(fs.readFileSync(manifestPath, 'utf8'));

        const ajv = new Ajv2020();
        const validate = ajv.compile(schema);
        const valid = validate(manifest);

        expect(valid, JSON.stringify(validate.errors)).toBe(true);
    });

    it('matches fresh regeneration', () => {
        const committed = JSON.parse(fs.readFileSync(manifestPath, 'utf8'));
        const generated = generate(configDir);

        expect(committed).toEqual(generated);
    });

    it('has every graph entity present with correct surfaces', () => {
        const manifest = JSON.parse(fs.readFileSync(manifestPath, 'utf8'));
        const graphFiles = fs.readdirSync(path.join(configDir, 'graph')).filter((f) => f.endsWith('.graphql'));

        let seen = 0;
        for (const filename of graphFiles) {
            const entity = filename.slice(0, -'.graphql'.length);
            const e = manifest.entities[entity];

            expect(e, `entity '${entity}' missing from manifest`).toBeDefined();
            expect(e.surfaces.graph.kind).toBe('graphql');

            const hasJsonSchema = fs.existsSync(path.join(configDir, 'json', `${entity}.schema.json`));
            if (hasJsonSchema) {
                expect(e.surfaces.api?.kind).toBe('rest');
            } else {
                expect(e.surfaces.api).toBeUndefined();
            }
            seen++;
        }
        expect(seen).toBe(Object.keys(manifest.entities).length);
    });
});
```

## Task 5: Serve `GET /manifest` over HTTP

**Files:**
- Modify: `examples/farm/manifest.ts` (add a route-mounting helper)
- Create: `examples/farm/index.ts` (new entrypoint, replaces reliance on `@tailoredshapes/meshql-cli`)
- Modify: `examples/farm/package.json` (dependencies + `build` script)
- Test: `examples/farm/test/manifest-serving.spec.ts`

**Two things discovered during planning, both resolved by this task:**
1. A committed `manifest.json` that's never served over HTTP is useless to a client — this is required, not optional (spec review finding).
2. `@tailoredshapes/meshql-cli`'s `package.json` declares `"exports": {".": "./dist/index.js"}`, but its build only ever produces `dist/cli.js` (confirmed: `core/cli/tsconfig.json`'s `include` is `src/**/*`, and `src/` only contains `cli.ts`) — so `import ... from '@tailoredshapes/meshql-cli'` does not actually resolve. This is pre-existing drift, unrelated to this plan; rather than fix the shared `core/cli` package (out of scope), this task sidesteps it by having `examples/farm` call `@tailoredshapes/meshql-server`'s `init` directly — which is also more consistent with how the Java and Rust examples are structured (each example composes the server library directly, not through a generic CLI wrapper).

- [ ] **Step 3: Add `mountManifestRoute` to `manifest.ts`**

```typescript
import { Application } from 'express';

/** Mounts GET /manifest, serving the given pre-serialized JSON string as-is. */
export function mountManifestRoute(app: Application, manifestJson: string): void {
    app.get('/manifest', (_req, res) => {
        res.type('application/json').send(manifestJson);
    });
}
```

- [ ] **Step 6: Write the entrypoint**

Create `examples/farm/index.ts`:
```typescript
import * as fs from 'fs';
import * as path from 'path';
import { init, Config } from '@tailoredshapes/meshql-server';
import { MongoPlugin } from '@tailoredshapes/meshql-mongo_repo';
import { mountManifestRoute } from './manifest';
const parser = require('@pushcorn/hocon-parser');

async function main() {
    const configFile = path.resolve(__dirname, 'config/config.conf');
    const config: Config = await parser.parse({ url: configFile });

    const app = await init(config, { mongo: new MongoPlugin() });

    const manifestPath = path.resolve(__dirname, 'config/manifest.json');
    const manifestJson = fs.readFileSync(manifestPath, 'utf8');
    mountManifestRoute(app, manifestJson);

    await app.listen(config.port);
    console.log(`Farm example running on port ${config.port} — manifest at /manifest`);
}

main().catch((err) => {
    console.error('Failed to start farm example:', err);
    process.exit(1);
});
```

Note: this reads `config/manifest.json` (the **committed** file) at startup, not a live call to `generate(...)` — the generator is a dev-time authoring tool, not part of the request path (matching the Java port and the "contract is the document" principle from the 2026-07-07 meshql-changes design doc).
